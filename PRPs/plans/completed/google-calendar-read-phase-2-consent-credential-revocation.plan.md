## Source

## Summary

This phase turns FR-030 from a terminal ritual into a product surface. An authenticated request mints a single-use, short-lived `state` nonce and hands back a Google consent URL for the two readonly scopes; the unauthenticated callback validates and consumes that nonce before it will talk to Google at all; the refresh token lands in D1; and disconnect revokes at Google and deletes locally, succeeding even when Google refuses. Two measured facts shape the design more than the PRD anticipated: the callback route must be added to `run_worker_first` or the SPA swallows it, and `fetchMock` no longer exists in the pinned test pool — so the Google client takes an injected `fetch`, which also happens to be the cleanest way to assert what an outbound request did and did not carry.

## User Story

```
As the owner of Praesto
I want to connect and disconnect my Google calendar from inside the app
So that granting and revoking access is something I do deliberately, and revoking never costs me any of my own data
```

## Problem Statement

Praesto can reach the owner's Google calendar today only because chore C11 minted a refresh token by hand and pasted it into a Worker secret. Nothing in the product grants that access, and nothing revokes it — FR-030 asks for both, under explicit consent, with 100% of local data preserved on disconnect. Worse, the credential's current home is a Worker secret, which a runtime OAuth flow cannot write: an in-app connect has nowhere to put what it obtains.

## Solution Statement

Add three routes and two tables. `POST /api/google/connect` (authenticated) mints a nonce row and returns a consent URL requesting exactly `calendar.events.readonly` and `calendar.calendarlist.readonly` with `access_type=offline`. `GET /oauth/callback` (unauthenticated, and outside `/api/*` so the bearer gate structurally does not apply) refuses any `state` it did not mint, did not keep unexpired, or already consumed — making no outbound request before that check passes — then exchanges the code and stores the refresh token, consuming the nonce in the same operation. `DELETE /api/google/connection` posts the token to Google's revoke endpoint and deletes the local credential and selection regardless of Google's answer. All Google I/O goes through one client module that takes a `fetch`-shaped function, defaulting to the global, so tests can both fake responses and inspect the request that was sent.

export const requireToken = createMiddleware<{ Bindings: Env }>(async (c, next) => {
  const expected = c.env.API_BEARER_TOKEN;
  if (!expected) {
    // Fail closed: an unconfigured secret must never mean "open to the world".
    return c.json({ error: "Server misconfigured: API_BEARER_TOKEN is not set" }, 500);
  }

  const header = c.req.header("Authorization") ?? "";
  const presented = header.startsWith("Bearer ") ? header.slice("Bearer ".length) : "";
  if (!presented || !timingSafeEqual(presented, expected)) {
    return c.json({ error: "Unauthorized" }, 401);
  }

  await next();
  return;
});

- **Reading any calendar data.** No `calendarList.list`, no `events.list`, no mapper. Phase 3 owns all of it.
- **Any UI.** No connect button, no settings screen, no pt-BR copy. Phase 4 owns the surfaces; this phase ships routes a human can drive with `curl` and the browser's address bar.
- **Anything written to Google.** The only non-GET requests in the whole unit are the token exchange and the revoke POST, both of which act on our own grant.
- **Persisting event data** — still nothing. The two new tables hold a credential and a nonce.
- **Touching `scheduled()`** — nothing is polled.
- **Including the credential in the FR-042 export.** Decided here rather than left open: an export containing a live refresh token would turn every backup file into a credential, and the export's purpose is the owner's *data*, not his access grants. The exclusion is explicit and documented in the export's own manifest when unit 5 lands, so it is a stated boundary rather than a silent gap.
- **Retiring the `GOOGLE_REFRESH_TOKEN` Worker secret.** It stays as C11 left it. Deleting a working credential while its replacement is unproven would be gratuitous; phase 3 decides its fate once a D1-stored token has actually served a request.

## Acceptance Criteria

- **AC-A1 (PRD AC-2):** Given the OAuth callback route, when it is called with a `state` that was never minted, or was already consumed, or is past its expiry, then it answers 4xx, the injected `fetch` records **zero** outbound calls, and no `google_connections` row exists afterwards.
- **AC-A2 (PRD AC-3):** Given a minted, unconsumed, unexpired `state` and a code, when the callback runs, then the code is exchanged at `https://oauth2.googleapis.com/token`, a refresh token is stored, the nonce is marked consumed, and replaying the identical callback URL then answers 4xx and changes no row.
- **AC-A3 (PRD AC-4):** Given a stored connection and N Task rows, when `DELETE /api/google/connection` is called, then the revoke endpoint receives the token, the credential and any calendar selection are gone, and the Task count is still N with no row modified.
- **AC-A4 (PRD AC-5):** Given the revoke endpoint answers non-2xx or throws, when disconnect runs, then the local credential is still deleted and the route reports success.
- **AC-A5 (PRD AC-1):** Given an authenticated request to `POST /api/google/connect`, when it succeeds, then the returned consent URL requests exactly the two readonly scopes and no other, carries `access_type=offline`, and its `state` matches a freshly persisted, unconsumed, unexpired `oauth_states` row.
- **AC-A6 (PRD AC-2) (config-only):** Given the deployed configuration, when a navigation request hits `/oauth/callback`, then the Worker handles it rather than the SPA — `run_worker_first` includes `/oauth/*`. Without this the route is unreachable in production while passing every test locally. Asserted against the config file rather than against behaviour, because no local test can observe the asset router — the same honesty the PRD applies to its own `(manual)` criteria.
- **AC-A7 (PRD AC-1):** Given every route added under `/api/google`, when called without a bearer token, then each answers 401 — and `src/worker/auth.ts` is byte-unchanged, so the callback's exemption comes from its path prefix and never from a conditional in the gate.

## Notes

Current value of `tdd` in `docs/context/methodology.md`: **true**. Test-first ordering — the test pair (test-writer/test-reviewer) produces the initial test suite from the Acceptance Criteria above, before the Implementer runs.

**Two measured facts changed this plan before it was written.**

1. **`/oauth/callback` would never have run.** `wrangler.jsonc` sets `not_found_handling: "single-page-application"` with `run_worker_first: ["/api/*"]`, and its own comment states that navigation requests are served `index.html` from asset storage and never reach the Worker. Google's redirect is a navigation request to a path outside `/api/*`. Adding `/oauth/*` to `run_worker_first` fixes it with no change on the Google side, since C11 already registered exactly this redirect URI. This is also why the security argument improves on the PRD's: the callback's exemption from the bearer gate is now a *different path prefix*, not a conditional inside `auth.ts`.

2. **`fetchMock` is gone.** Cloudflare removed the `cloudflare:test` `fetchMock` export in vitest-pool-workers 0.13.x, during the Vitest 3 → 4 migration (https://developers.cloudflare.com/workers/testing/vitest-integration/migration-guides/migrate-from-vitest-3-to-vitest-4/), and now recommends mocking `globalThis.fetch` or using MSW (https://developers.cloudflare.com/workers/testing/test-harness/integrations/). Verified empirically against this repo's pinned 0.20.1: `cloudflare:test` exports `SELF, abortAllDurableObjects, adminSecretsStore, applyD1Migrations, createExecutionContext, createMessageBatch, createPagesEventContext, createScheduledController, env, evictAllDurableObjects, evictDurableObject, getQueueResult, introspectWorkflow, introspectWorkflowInstance, listDurableObjectIds, reset, runDurableObjectAlarm, runInDurableObject, waitOnExecutionContext` — no `fetchMock`. Adding MSW would be a new dependency, which ADR-0005 makes a deliberate decision rather than a convenience. Dependency injection needs none, and serves the acceptance criteria better: proving a request carried `timeMin` and did NOT carry `syncToken` (phase 3's AC-6) requires inspecting the outbound request, which an injected function hands over directly. `vi.stubGlobal("fetch", …)` was also verified to work under workerd in this pool (a stub returned 418 as written) and stays the documented escape hatch where injection cannot reach.

**What this phase cannot finish.** The OAuth consent screen requires a human in a browser approving at Google. Everything here is implementable and testable with the outbound `fetch` faked, but the real re-consent, the real refresh token, and the proof that the flow works against Google are the owner's to perform. The phase is done when the routes are correct and tested; it is *verified* only after the owner walks the flow once.
