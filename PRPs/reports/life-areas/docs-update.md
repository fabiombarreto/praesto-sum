## Candidate Decisions (for operator review)

The following were observed in the diff but are implementation choices or inferred patterns, so they were NOT written to `docs/decisions.md` or `docs/anti-patterns.md` per the PRESERVE-ENTIRELY rule. The operator should review them and add them manually if they are stable:

- **An effect registered once must read changing values through a latest-callback ref.** `TodayScreen`'s `visibilitychange` effect (`[]` dependencies) closed over the first render's `refresh` and so its `filter`; the fix is `refreshRef.current = refresh` and `refreshRef.current()`, the idiom `useConnectivity` already uses for `onOnline`. Two instances of the idiom now exist. It is stated in code comments and in the plan as a defect, not as a project rule. If the owner wants it recorded, the natural form is an anti-pattern ("a once-registered effect calling a render-scoped function") or a convention in `docs/context/conventions.md`.
- **The filter's `"none"` is its own value and must never go through the sheet's `lifeAreaIdFromChoice`.** `life-area-assign.ts` and `FilterSheet.tsx` now carry comments saying the sheet maps `NO_AREA_VALUE` to `null` (right for "no area") while the filter keeps `"none"` (where `null` means "no filter"); the Level 2 gate greps for it. A mapping of one literal through two vocabularies is the kind of footgun that recurs; as written it is a code comment, not a rule.
- **A long applied-filter label is capped at the call site, not in the shared primitive.** `FilterChips.tsx` applies `max-w-40 truncate` to its own label span and leaves `Chip` byte-identical, after a measurement (`phase-4/chip-overflow-measurement.md`, `Decision: keep Chip as is`). It is an implementation choice recorded in its own measurement file; it would become a convention only if a second owner-named label needs the same cap.
- **Static width estimates were pessimistic and a measurement decided.** The plan's estimate of a 40-character chip (306 to 346 px unpressed) was above the measured 320 px, and its consequence ("the sheet scrolls sideways") did not occur because the wrapping group is `overflow: visible`. An observation about method, not a project rule; noted so a future "conscious ✘ from an estimate" is measured before it is carried.
