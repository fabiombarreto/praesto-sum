# ADR-0005: Implementation stack — React 19 SPA + Vite + Hono + Drizzle ORM on a single Cloudflare Worker

> **Purpose:** Record the resolution of pending decision 3 — the concrete implementation stack — its context and its consequences.
> **Update when:** Never after acceptance — a change of course produces a new ADR that supersedes this one.

- **Date:** 2026-08-03
- **Related:** [ADR-0003](ADR-0003-store-canonical-data-in-cloudflare-d1.md), [ADR-0004](ADR-0004-single-pwa-as-sole-interface.md); QA-002, QA-004, CON-001, CON-002

## Context

[ADR-0003](ADR-0003-store-canonical-data-in-cloudflare-d1.md) fixed the canonical data store (Cloudflare D1) and the runtime (Cloudflare Workers, free plan, single-user token-gated API, cron-triggered Reminder scheduler). [ADR-0004](ADR-0004-single-pwa-as-sole-interface.md) fixed the interface: a single installable responsive PWA served by the same deployment, with Web Push for Reminders. This ADR closes the last pre-implementation decision: the PWA framework and its integration with the Worker, the D1 access and migration layer, and the tooling.

Driving forces: QA-004/CON-002 (solo sustainability — the owner must understand everything after months away), longevity (a multi-year project with irregular cadence — ecosystem churn is risk #1; stability over novelty), CON-001 (first-class Windows 11 support), first-class free-plan support for Workers + D1 + static assets + cron + Web Push, a no-hacks PWA, one-command local dev after months idle, and affinity with AI-assisted development (widely documented mainstream patterns).

Ecosystem facts grounding this decision (researched Aug 2026): Cloudflare officially recommends Workers with Static Assets (not Pages) for new SPA+API projects — Pages lacks cron triggers entirely; `@cloudflare/vite-plugin` is GA (1.x) and runs the real Worker in workerd during dev; Drizzle ORM is marked Production Ready with D1, and its generated SQL migrations are applied via `wrangler d1 migrations`; Web Push from Workers is officially documented via the classic `web-push` library with the `nodejs_compat` flag (edge-native alternatives such as `@pushforge/builder` exist); the free tiers exceed single-user scale by orders of magnitude; Windows 11 is officially supported, with one known workerd crash mitigated by keeping the MS VC++ Redistributable current.

Owner profile (confirmed 2026-08-03, the panel's tie-breaker): most experienced with **React**, already fluent in **TypeScript**, willing to adopt whatever fits the project best, explicitly accepts ~one weekend/year of mechanical upgrades in exchange for HMR and end-to-end types, and chose **Drizzle ORM** over raw SQL. The evaluation panel's top two options tied on merit; this profile broke the tie decisively toward the paved path.

## Decision

We will build the PWA as a **React 19 single-page application in TypeScript** — explicitly no meta-framework, no SSR, no RSC; **this is a final position, not deferred debt** — bundled by **Vite** with the official **`@cloudflare/vite-plugin`** and served as static assets by the same Worker that hosts the API. PWA concerns (manifest, installability, app-shell caching) are handled by **`vite-plugin-pwa` in `injectManifest` mode** with a hand-owned `src/sw.ts` containing the push and notificationclick handlers.

The API is **Hono 4** running in the Worker: bearer-token middleware on every route (ADR-0003), JSON routes under `/api/*`, and the `scheduled()` handler in the same entrypoint driving the Reminder cron. Web Push is sent with the **`web-push` library under `nodejs_compat`** (Cloudflare's documented path), with a dedicated integration test that generates and validates the VAPID JWT — push failure is silent, so it must be tested.

D1 access goes through **Drizzle ORM** (`drizzle-orm/d1`), with `src/worker/db/schema.ts` as the single source of entity types flowing from the database to the UI. Migrations are plain numbered SQL files generated by `drizzle-kit generate` and **always applied via `wrangler d1 migrations apply`**, locally and remotely.

Tooling: **npm** as package manager (single package, no workspaces), **all dependency versions pinned exact** (`save-exact`) with the lockfile committed and `npm ci` on return — upgrades are deliberate, changelog-in-hand events, never incidental. Testing: **Vitest with `@cloudflare/vitest-pool-workers`** exercising Hono routes, `scheduled()` and the data layer against an ephemeral local D1 inside real workerd; domain logic (recurrence, dates) lives in pure functions unit-tested with plain Vitest; UI is tested manually in the MVP. Lint/format: **Prettier** plus **`tsc --noEmit` in strict mode** as the mandatory `check` gate, with a minimal ESLint flat config (typescript-eslint recommended presets only).

Repository layout: single package — `src/app/` (React SPA + typed api-client), `src/sw.ts`, `src/shared/` (pure domain logic + shared types), `src/worker/` (fetch + scheduled entry, `routes/`, `push/`, `db/`), `migrations/`, `public/` (manifest, icons), `test/`, `wrangler.jsonc` (static assets with `single_page_application`, D1 binding, cron trigger), `vite.config.ts`, `drizzle.config.ts`, and per-target tsconfigs with project references so an app/worker boundary violation is a compile error. One command runs everything locally (`npm run dev`: HMR + real workerd + local D1); one command ships everything (`vite build && wrangler deploy`).

## Alternatives considered

- **Minimal artisanal stack (Preact + hand-written router/service worker + raw esbuild, no Vite)** — rejected: it tied the paved path on the weighted criteria but loses on the owner's profile: it trades the officially recommended Cloudflare toolchain (HMR, single dev process, dev/prod parity in workerd) for hand-maintained glue code (router, SW cache versioning) that demands judgment exactly where a returning-after-months solo dev is weakest, and it solves a problem (hand-rolled VAPID signing) the platform has since solved officially. Documented fallback if dependency weight ever becomes the dominant pain.
- **React Router v7/v8 framework mode (ex-Remix) on the official Cloudflare template** — rejected: SSR and hydration add a whole mental model with zero payoff for a token-gated single-user app, the yearly-major cadence is a standing maintenance commitment, and no meta-framework provides the product's most critical feature (Web Push / service worker).
- **SvelteKit or Nuxt on Cloudflare** — rejected: their adapters generate the Worker entry, complicating the `scheduled()` cron handler Reminders depend on; Svelte shipped two mental-model ruptures in ~2 years (Svelte 5 runes, SvelteKit 2); NuxtLabs was acquired by Vercel (Jul 2025), aligning its commercial gravity with a competing platform. Moot after the owner confirmed React experience.
- **Next.js via OpenNext** — rejected: the highest-churn path on Cloudflare today; a third-party shim chasing Next.js internals.
- **Raw parameterized SQL repositories instead of an ORM** — a sanctioned, sustainable alternative; the owner explicitly chose Drizzle for end-to-end types. Drizzle remains thin enough that falling back to raw SQL would not change the migration files.
- **Kysely (community `kysely-d1` dialect)** — rejected: community-maintained dialect with weaker guarantees than Drizzle's officially documented, production-ready D1 support.

## Consequences

- Positive: the entire product ships as one Worker deployment (static assets + API + cron) on the free plan, one command to develop and one to deploy; dev runs in real workerd with a local D1, so dev/prod parity is structural; types flow from the Drizzle schema to the React components, turning schema drift into compile errors; every piece is the most-documented member of its category — minimizing AI hallucination during assisted development and matching the owner's existing React/TypeScript experience; exact pinning plus committed lockfile means the project builds identically after months idle.
- Negative / accepted trade-offs:
  - ~One weekend per year of mechanical upgrade work (Vite yearly majors, wrangler platform evolution — the latter already accepted in ADR-0003), explicitly accepted by the owner.
  - A heavy `node_modules` tree and npm-audit noise inherent to the React/Vite ecosystem.
  - Drizzle is still 0.x — minor versions may break API; hence the hard pin-and-deliberate-upgrade rule.
  - The service worker update flow (skipWaiting, cache versioning) must be tested before the MVP ships — a stale app shell is the classic PWA failure.
  - Web Push depends on `nodejs_compat` behavior in Workers — mitigated by the dedicated VAPID integration test and the `@pushforge/builder` escape hatch.
  - Ecosystem social pressure ("SPAs are dead", RSC) is a behavioral risk countered by recording SPA+Vite as a final position in this ADR.
