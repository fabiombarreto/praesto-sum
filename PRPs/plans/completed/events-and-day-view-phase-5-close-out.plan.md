## Summary

Phases 1 to 4 built the Event end to end in code; what is left is to prove it, document it and put it in the owner's hands. This phase splits cleanly in two. **Part A** is everything the pipeline can build and verify in the worktree: the documentation amendments the earlier phases deliberately left for here (the glossary entry *Compromisso*, `domain-model.md` and `docs/domain/areas/events.md` agreeing with ADR-0016, the layout standard's §2 items 3, 4 and 11, §3, §5, §6 and its History, the visual-identity microcopy rows the owner approved, the requirement traceability, the roadmap row, the architecture documents, `docs/api-reference.md`, the stale derived-document lines, `CLAUDE.md`); the AC-33 invariants, including making `scripts/check-mirror-inventory.mjs` pass — which already fails on `main` on two lines that read Praesto's OWN Reminder entity, and which this plan fixes by pinning exactly those two lines in the script (file plus whole-line shape) rather than by touching shipped code or loosening the rule — and a permanent guard so the script can never rot unwired again; the unit-level UI/UX checklist roll-up; and the owner hand-off records (the `v0.14.0` release runbook and an OWED `device-proof.md`). **Part B** is owner-only and is recorded, not performed: commit and pull request, merge, chore C6 on the latest real snapshot, the remote migration `0007`, the tag and deploy, the device proof, and the drill on a real snapshot that holds an event. The unit stays `in-progress`; nothing in this phase claims AC-31 or AC-32. Test-first applies to the part that is decidable in the Node-side `docs` project: two new suites, `test/mirror-inventory.test.ts` (the script, run for real against the repository and against planted trees) and `test/close-out-docs.test.ts` (the documentation facts and the hand-off records), written by the test pair before the Implementer runs. ## Problem Statement

Phases 1 to 4 left the documentation behind the code on purpose: the glossary does not name *Compromisso*, `domain-model.md` still draws an edge from Life Area to Event that ADR-0016 deferred, the layout standard still says the local rows are inert and that the sheet "is not described here yet", the roadmap says all five phases are `pending` and nothing is built, and `CLAUDE.md` still carries a point-in-time test count. The AC-33 invariants have only been checked by hand and the mirror-inventory tripwire — wired into no npm script, no test and no deploy step — has been failing on `main` on two lines that are not Google data at all. And the unit cannot be deployed: the release `v0.14.0` has no runbook that orders the pre-migration drill, the remote `0007`, the tag, the deploy and the post-deploy drill, and the device proof has no record to fill in. Until those exist the unit's exit signal ("the owner created a local commitment without missing any field Google has") has nowhere to be observed.

## Solution Statement

Part A writes the documentation and the records, test-first. The decidable facts of AC-34 and of the hand-off records go into `test/close-out-docs.test.ts`; the tripwire script's behaviour goes into `test/mirror-inventory.test.ts`, which spawns the real script against the repository and against planted trees, so `npm test` now runs the tripwire on every run. The script is extended with a two-entry exemption list pinned to a file AND to the whole trimmed line (`src/app/api.ts` `return body.reminders;` and `src/shared/export.ts` `reminders: tables.reminders,`), because the rule exists to keep Google's `attendees`, `reminders` and `recurrence` out of Praesto and these two lines read Praesto's own `{ reminders: ReminderDto[] }` response and its own export envelope key. Rewriting those two shipped lines into a destructuring form to dodge a regex would change production code for the sake of a check and normalise exactly the evasion shape the script cannot see; widening the script to a directory or a name would weaken it. `attendees` and `recurrence` get no exemption at all. Part B is written as a runbook of nine ordered owner steps and an OWED device-proof record that claims nothing.
