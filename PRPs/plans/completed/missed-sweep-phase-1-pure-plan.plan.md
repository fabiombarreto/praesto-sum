## Summary

Phase 1 adds one new pure module in `src/shared`, `missed-sweep.ts`, exporting a planning function that answers, for one Recurrence Series: has its open occurrence been superseded as of `today` (the series' local day), which cycles were missed, where does the successor fall, whether the successor should carry Reminders, and whether the series ends. It composes `nextOccurrence` from `src/shared/recurrence.ts` (never editing it), handles calendar and completion anchors, `until` and `count` end conditions, a series the owner ended, the 366-cycle catch-up bound, and the repair of an active series with no open occurrence. No route, schema, worker code or UI is touched; Phase 2 writes the plan to D1.

## User Story

As the owner, I want the decision "was this occurrence missed and what comes next" to be a pure, exhaustively tested function, so that the cron in Phase 2 can record misses and keep every series alive without any date edge being decided for the first time against live data.

## Problem Statement

When the owner does not do an occurrence of a recurring Task, nothing happens: the occurrence stays open and overdue forever, the series stops advancing, and no record says that cycle failed. Units 11 and 12 read exactly the `missed` rows this unit is the first to write. Narrowed to Phase 1: the decision logic that says when an occurrence is superseded, which cycles were missed and what the successor is does not exist yet, and it is the risky part.

## Solution Statement

One new pure function in `src/shared/missed-sweep.ts`. Given the series rule, `status`, `doneCount`, `missedCount`, the open occurrence's date (or the last closed occurrence's date for the repair) and `today`, it returns a plan value. The supersede date is computed by calling `nextOccurrence` on a copy of the rule with `endKind: "never"` (so the last allowed occurrence can still be recorded as missed), while the real end condition is checked separately for intermediate and successor dates. Catch-up rows are generated by repeated stepping, capped at 366 missed cycles per call; a successor that the cap leaves still dated before `today` is flagged as carrying no Reminders.

Proposed contract (names are the plan's recommendation; the test pair derives the tests from the PRD's AC text, and any name it needs that differs is reconciled in the suite, not by editing `recurrence.ts`):

- `planMissedSweep(input: MissedSweepInput): MissedSweepPlan`
- `MissedSweepInput`: `{ rule: RecurrenceRule; status: "active" | "ended"; doneCount: number; missedCount: number; openOccurrenceDate: string | null; lastClosedOccurrenceDate: string | null; today: string }`
- `MissedSweepPlan`: `{ closeOpenAsMissed: boolean; extraMissedDates: string[]; successor: { date: string; armReminders: boolean } | null; endSeries: boolean; missedCountDelta: number }` where `missedCountDelta` equals the open occurrence's miss (when closed) plus `extraMissedDates.length`.

```ts
// SOURCE: src/shared/recurrence.ts:299-312
export function nextOccurrence(rule: RecurrenceRule, args: NextOccurrenceArgs): string | null {
  let candidate: string;
  if (rule.anchorMode === "completion") {
    if (args.completedOn === undefined) {
      throw new TypeError(
        "nextOccurrence: rule.anchorMode is 'completion' but completedOn was not provided",
      );
    }
    candidate = stepToNextOccurrenceFromCompletion(rule, args.completedOn);
  } else {
    candidate = findNextTrackDate(rule, args.after);
  }
  return isWithinEndCondition(rule, candidate, args.closedCount) ? candidate : null;
}
```
Copied by: Tasks 1, 2 and 3 (every step calls `nextOccurrence`; completion-anchored rules always pass `completedOn`).

```ts
// SOURCE: src/shared/recurrence.ts:266-279
function isWithinEndCondition(
  rule: RecurrenceRule,
  candidate: string,
  closedCount: number | undefined,
): boolean {
  if (rule.endKind === "until") {
    return rule.untilDate === null || candidate <= rule.untilDate;
  }
  if (rule.endKind === "count") {
    const count = closedCount ?? 0;
    return rule.maxCount === null || count < rule.maxCount;
  }
  return true;
}
```
Copied by: Task 2 (the end condition is applied through `nextOccurrence` with `closedCount = doneCount + missedCount + <misses planned so far>`, D6; the copy of the rule with `endKind: "never"` only finds the supersede date).

## Acceptance Criteria

- **AC-A1 (PRD AC-1):** Given the same inputs, the planning function returns identical plans when called twice with the system clock faked a year apart, and the module imports nothing from `src/worker/` or `src/app/`.
- **AC-A2 (PRD AC-2):** An open occurrence not yet superseded changes nothing (daily `2026-10-01` on `2026-10-01`; monthly `2026-10-05` on `2026-11-04`), and on `2026-11-05` marks `2026-10-05` missed with the successor on `2026-11-05`.
- **AC-A3 (PRD AC-3):** A daily series whose open occurrence is `2026-10-01`, planned for `2026-10-04`, closes `2026-10-01`, adds missed `2026-10-02` and `2026-10-03`, names the successor `2026-10-04` and grows the missed count by 3.
- **AC-A4 (PRD AC-4):** An open occurrence 400 days before today yields at most 366 missed cycles and a successor at the next unswept date, planned without Reminders while still dated before today; repeating the plan from it reaches today's occurrence without losing a cycle or looping without end.
- **AC-A5 (PRD AC-5):** A completion-anchored daily rule with `interval: 3` and open occurrence `2026-10-01` changes nothing for today `2026-10-03`, and for `2026-10-04` marks `2026-10-01` missed with the successor `2026-10-04`.
- **AC-A6 (PRD AC-6):** A monthly `count: 3` series with `doneCount: 1`, `missedCount: 1` and open occurrence `2026-10-05`, for today `2026-11-05`, marks `2026-10-05` missed, plans no successor and ends the series.
- **AC-A7 (PRD AC-7):** A daily `until: "2026-10-03"` series with open occurrence `2026-10-01`, for today `2026-10-10`, marks `2026-10-01` missed, adds missed `2026-10-02` and `2026-10-03`, plans nothing after `2026-10-03`, no successor, and ends the series.
- **AC-A8 (PRD AC-8):** An owner-ended series with open occurrence `2026-10-05` (monthly on the 5th), for today `2026-11-05`, marks `2026-10-05` missed and plans nothing else.
- **AC-A9 (PRD AC-9):** An active daily series with no open occurrence and last closed occurrence `2026-09-01`, for today `2026-10-04`, plans exactly one open occurrence on `2026-10-04` and no missed rows; when the rule has no date on or after today, it plans no occurrence and ends the series.
