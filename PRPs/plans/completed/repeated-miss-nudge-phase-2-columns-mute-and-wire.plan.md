## Source PRD

## Summary

This phase adds the persisted state the nudge cron step (phase 3) will read and write, and the one owner-facing way to change it. Two columns are added to `recurrence_series` — `nudged_at` (system state, the exactly-once marker) and `nudge_muted` (owner preference, default false) — through a migration `0006` generated by drizzle-kit. `nudge_muted` is carried by the wire `SeriesDto` and writable through the closed `EDITABLE_SERIES_FIELDS` allowlist of `PATCH /api/series/:id`, validated as a boolean; `nudged_at` is never on the series wire, but both columns ride in the FR-042 export row so a restore preserves the mute. Completing a series occurrence clears `nudged_at` inside the batch the complete route already runs. No cron, push or UI work happens here.

## User Story

As the owner of Praesto Sum
I want a series' nudge silence and "already nudged" marker to be stored, exported and cleared on completion
So that the phase-3 cron step can send exactly one push per run of misses and I can silence one series without touching any Reminder.

## Problem Statement

A naive "push for every miss" is noise the owner would mute at the operating-system level, taking his real Reminders with it. Before the cron can send exactly one notification per run, the system needs (a) a per-series exactly-once marker, (b) a per-series persistent silence the owner controls, and (c) a re-arm rule tied to a completion. None of that state exists today: there is no nudge, mute or "nudged at" code anywhere (PRD Research Summary, Technical Context gaps).

## Solution Statement

Two additive columns on `recurrence_series`, a generated migration, a wire field and an allowlisted PATCH key for the mute, the export row carrying both, and one extra assignment in the existing complete-route batch that clears the marker. The cron's claim-before-send and the sheet's switch are phases 3 and 4.

## Acceptance Criteria

- **AC-A1 (PRD AC-8):** Completing an occurrence of a series sets that series' `nudged_at` to NULL in the same batch that marks the occurrence `done`; a series whose marker was set and which is then completed is re-armed, and a `missed` close (the missed sweep) never clears it.
- **AC-A2 (PRD AC-11):** `PATCH /api/series/:id` with `{ "nudgeMuted": true }` (and `false`) persists the value on that series only; other series and every Reminder are unchanged.
- **AC-A3 (PRD AC-11):** A non-boolean `nudgeMuted` returns 400 and writes nothing; an unknown extra key in the same body keeps the route's existing rejection naming the key.
- **AC-A4 (PRD AC-14):** After migration `0006` is applied to a database with existing series, every row keeps its data, `nudge_muted` is false and `nudged_at` is null.
- **AC-A5 (PRD AC-14):** The FR-042 export's `recurrence_series` rows carry both `nudgedAt` and `nudgeMuted`, and the restore drill's field-level comparison restores both (a muted series stays muted after a restore).
- **AC-A6 (PRD AC-11):** The `/api/series` wire (`SeriesDto`) carries `nudgeMuted: boolean` and never `nudgedAt`.
