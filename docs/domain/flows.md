# Main user flows

> Non-technical descriptions of what the assistant does for its single user (the owner). Derived from the owner-validated requirements in `documentation/20-requirements/functional-requirements.md`.

## 1. Quick capture (the core habit)

Owner thinks of something to do → opens the assistant on whatever device is at hand and adds it in seconds, with as little friction as possible → sees it saved and stops worrying about remembering it.

## 2. Organizing the day

Owner opens the assistant → sees today's picture: tasks due or scheduled for today and (from Phase 2 on) the day's events in order → works through the day marking tasks done.

## 3. Being reminded

Owner attaches a reminder to a task or event, or creates a standalone one ("drink water at 3pm") → at the chosen moment the system sends a notification to the owner's phone or PC → owner perceives it and acts, without having had to remember anything.

## 4. Finding it again

Owner needs something noted before → types a text search → the system returns the matching tasks and events → owner opens the right one. ("I know I noted this somewhere" must never happen inside the assistant.)

## 5. Taking the data out

Owner asks for an export → the system produces complete files in open formats (JSON + iCalendar) → owner stores them wherever they want. This works on day 1, always — the owner's data is never hostage.

## 6. Recurring commitments (Phase 1–2)

Owner marks a task or event as repeating ("pay rent on the 5th", "meeting every Monday") → the system materializes the repetitions → owner sees each occurrence in its day without recreating anything.
